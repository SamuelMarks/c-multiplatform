# Deployment & App Store Guide: End-to-End

Because the core engine is written in C89 with a decoupled Platform Abstraction Layer, building for 6 different operating systems requires zero application code changes. This guide provides an exhaustive, step-by-step walkthrough for compiling, packaging, and publishing to every major storefront.

---

## 1. Web (HTML5 & WebAssembly)

The web target compiles the C application into WebAssembly using Emscripten, utilizing HTML5 Canvas for the OpenGL ES 2.0 (WebGL) renderer.

### Build & Optimization
We enforce strict `-O3` and Link-Time Optimization (LTO) for WASM to minimize payload size.
```bash
# Initialize Emscripten
source /path/to/emsdk/emsdk_env.sh

mkdir build_web && cd build_web
emcmake cmake .. \
    -DCMAKE_BUILD_TYPE=Release \
    -DCMAKE_C_FLAGS="-O3 -flto" \
    -DCMAKE_EXE_LINKER_FLAGS="-O3 -flto -s WASM=1 -s ALLOW_MEMORY_GROWTH=1"
emmake make
```

### Deployment Strategy
*   **Artifacts:** The build produces `index.html`, `app.js`, and `app.wasm`.
*   **MIME Types:** Ensure your web server (Nginx/Apache) serves `.wasm` with `application/wasm`. If using AWS CloudFront, ensure this MIME type is mapped.
*   **Compression:** WASM binaries compress remarkably well. Always enable Brotli (`.br`) or GZIP (`.gz`) on your edge network.
*   **Content-Security-Policy:** Your HTML file must include a CSP header. Ensure `script-src` allows the Emscripten glue code (use a nonce or hash) and `connect-src` allows any `c-abstract-http` fetch requests your app makes.

## 2. Windows (Microsoft Store)

Windows utilizes the MSVC compiler, bridging to Win32 (HWND) and WGL for rendering.

### Build
```bash
mkdir build_win && cd build_win
# Generate a 64-bit Visual Studio solution
cmake .. -A x64 -DCMAKE_BUILD_TYPE=Release
cmake --build . --config Release
```

### MSIX Packaging & Publishing
To publish to the Microsoft Store, you cannot simply upload an `.exe`. You must package it as an MSIX.
1.  **Manifest:** Create an `AppxManifest.xml` defining the `Identity`, `Properties`, and `Capabilities` (e.g., `<rescap:Capability Name="runFullTrust" />`).
2.  **MakeAppx:** Use the Windows SDK tool:
    `MakeAppx.exe pack /d "path\to\your\release\folder" /p "YourApp.msix"`
3.  **SignTool:** You must sign the MSIX before sideloading or testing. Use a Trusted certificate (or one generated by Partner Center).
    `SignTool.exe sign /fd SHA256 /a /f YourCert.pfx /p Password "YourApp.msix"`
4.  **Partner Center:** Navigate to the Windows Partner Center, reserve your app name, create a new submission, and upload the generated `.msixupload` bundle.

## 3. macOS (Mac App Store)

macOS uses Clang, bridging to Cocoa (NSWindow) and CGL.

### Build
```bash
mkdir build_mac && cd build_mac
# Generate an Xcode project
cmake .. -G Xcode
xcodebuild -project YourApp.xcodeproj -configuration Release
```

### Packaging, Signing, and Notarization
Apple has strict requirements for the Mac App Store.
1.  **Info.plist:** Ensure `CFBundleIdentifier`, `CFBundleVersion`, and `LSApplicationCategoryType` are set correctly.
2.  **Entitlements:** Create a `YourApp.entitlements` file. You *must* include `<key>com.apple.security.app-sandbox</key><true/>`.
3.  **Codesign:** Sign the generated `.app` bundle:
    `codesign --force --options runtime --sign "Apple Distribution: Your Name (TeamID)" --entitlements YourApp.entitlements build_mac/Release/YourApp.app`
4.  **Notarization (For non-Store distribution):** If distributing via DMG outside the store, you must notarize the app:
    `xcrun notarytool submit YourApp.dmg --keychain-profile "AC_PASSWORD" --wait`
5.  **Mac App Store:** Use the Transporter app (or Xcode Organizer) to upload your signed `.pkg` or `.app` to App Store Connect.

## 4. Linux (Flathub & Wayland)

Linux distribution builds against either X11/GLX or the modern Wayland/EGL stack.

### Build (Wayland Native)
```bash
mkdir build_linux && cd build_linux
# Explicitly enable the Wayland toggle
cmake .. -DCMAKE_BUILD_TYPE=Release -DUI_ENABLE_WAYLAND=ON
make
```

### Flatpak & Flathub
We recommend Flatpak over Snap or AppImage due to sandboxing and universal adoption.
1.  **Manifest:** Create `org.yourdomain.App.json` pointing to the Freedesktop runtime:
    ```json
    {
      "app-id": "org.yourdomain.App",
      "runtime": "org.freedesktop.Platform",
      "runtime-version": "23.08",
      "sdk": "org.freedesktop.Sdk",
      "command": "YourApp",
      "finish-args": [
        "--share=ipc", "--socket=wayland", "--socket=fallback-x11", "--device=dri"
      ]
    }
    ```
2.  **Build & Export:**
    `flatpak-builder build-dir org.yourdomain.App.json`
    `flatpak build-export repo build-dir`
3.  **Flathub:** Submit your manifest via a Pull Request to the `flathub/flathub` repository on GitHub.

## 5. iOS (App Store)

iOS uses Apple Clang and links against UIKit and EAGL.

### Build
You must provide a CMake toolchain file configured for iOS cross-compilation.
```bash
mkdir build_ios && cd build_ios
cmake .. -G Xcode \
    -DCMAKE_SYSTEM_NAME=iOS \
    -DCMAKE_OSX_ARCHITECTURES=arm64
xcodebuild -project YourApp.xcodeproj -configuration Release -sdk iphoneos
```

### TestFlight & App Store
1.  **Provisioning:** Log into the Apple Developer portal. Create an App ID and a Distribution Provisioning Profile.
2.  **Archive:** Open the Xcode project generated by CMake. Select your Target Device (Any iOS Device). Click `Product -> Archive`.
3.  **Validation:** In the Organizer window, validate the archive against your Provisioning Profile.
4.  **Upload:** Upload the binary. It will process on App Store Connect and become available for TestFlight internal/external testing.

## 6. Android (Google Play Store)

Android utilizes the Android NDK and `android.app.NativeActivity`, requiring zero Java code for the core UI.

### Build
You must use the CMake toolchain provided by your installed Android NDK.
```bash
export ANDROID_NDK=/path/to/android-ndk
mkdir build_android && cd build_android
cmake .. \
    -DCMAKE_TOOLCHAIN_FILE=$ANDROID_NDK/build/cmake/android.toolchain.cmake \
    -DANDROID_ABI=arm64-v8a \
    -DANDROID_PLATFORM=android-21 \
    -DCMAKE_BUILD_TYPE=Release
make
```
*Note: You must build for all target ABIs (`arm64-v8a`, `armeabi-v7a`, `x86_64`) if producing a universal APK.*

### Gradle Packaging & AAB
1.  **Wrapper Project:** Place the compiled `libYourApp.so` into the `src/main/jniLibs/arm64-v8a/` directory of a standard Gradle project.
2.  **Manifest:** Your `AndroidManifest.xml` must route the main intent to the native activity:
    ```xml
    <activity android:name="android.app.NativeActivity">
        <meta-data android:name="android.app.lib_name" android:value="YourApp" />
    </activity>
    ```
3.  **App Bundle:** Build the AAB using Gradle:
    `./gradlew bundleRelease`
4.  **Signing:** Sign the AAB using `jarsigner` or `apksigner` with your release Keystore.
5.  **Google Play Console:** Upload the signed `.aab` file. Google Play will automatically generate device-optimized APKs from the bundle.
